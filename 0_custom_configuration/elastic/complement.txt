# Elastic Defend complement profile: telemetry that Elastic Defend did not record in the lab
# comparison, plus evidence of Elastic Defend being stopped or tampered with.
# README.md explains the choice for each event.
#
# Paths are relative to the repository root. Upstream modules that this profile leaves out are
# listed with the reason, next to their event. Exclusions are kept only when an attacker can't
# satisfy them without administrator rights.

# Switchboard: every event gets an explicit filter. Events 2, 6, 8, 9, 17/18, 19-21, and 25 are
# logged in full, minus the exclusions below. Do not add include modules for these events: one
# include rule turns an event into an allow-list. All other events log only what the include
# modules below select.
0_custom_configuration/elastic/modules/complement_base.xml

# Event 1: security tools starting or restarting, the partner of the Event 5 module. Elastic Defend
# reported only five elastic-endpoint.exe process records across both lab hosts all day, while Sysmon
# logged 105 starts on one. About 134 records a day on the lab host.
1_process_creation/include_security_process_creation.xml

# Event 2: file creation time changed. Logged in full: 91 records a day in the lab.
# Left out: every upstream exclusion. Each one matches a process name, a path suffix, or a folder
# that any user can create: exclude_chrome.xml, exclude_nvidia.xml, exclude_onedrive.xml,
# exclude_setups.xml, exclude_slack.xml, and exclude_teams.xml.

# Event 5: security tools stopping, including Elastic Agent, its collector, and Elastic Defend.
5_process_ended/include_security_process_termination.xml

# Event 6: driver loads. Logged in full: 3 records a day in the lab. Attackers load vulnerable signed
# drivers to stop security tools, and nobody has checked whether Elastic Defend records driver loads.
# Left out: exclude_intel_drivers.xml and exclude_microsoft_drivers.xml. They trust drivers by
# signer, but Intel's iqvw64e.sys is a well-known vulnerable driver, and many third-party drivers
# carry a Microsoft hardware-compatibility signature.

# Event 8: remote threads. Logged in full: 8 records a day in the lab.
# Left out: every upstream exclusion. exclude_generic_windows_processes.xml drops svchost.exe,
# services.exe, winlogon.exe, and csrss.exe as sources, which also hides Ctrl-Inject.
# exclude_wmi.xml drops threads started from WmiPrvSE.exe, and exclude_google_chrome.xml drops any
# injection into Chrome. None of them removed anything in the lab.

# Event 10 (provisional): every LSASS open except the query-only masks, which can't read memory.
# A list of read masks would miss any mask it doesn't name. In the lab this logged 13 records a day,
# all wmiprvse.exe with 0x1410. No credential-access test has been run yet, and Elastic Defend's
# credential hardening was off in the lab comparison. Keep exclude_elastic.xml: Elastic Defend made
# 637,803 Event 10 records before the lab's own exclusion took effect.
# Left out: include_lsass_access.xml, which lists read masks, and exclude_lsass_noise.xml, which drops
# taskmgr.exe by name and so hides LSASS dumps made with Task Manager.
0_custom_configuration/elastic/modules/10_process_access/include_lsass_access_all.xml
10_process_access/exclude_query_only_access.xml
10_process_access/exclude_elastic.xml

# Event 11: files written into the Elastic folders by other processes.
11_file_create/include_elastic_sensor_file_tampering.xml

# Events 17/18: named pipes. None of the left-out vendor applications ran in the lab, so their
# exclusions removed nothing from the measured data. Add one back if a rerun shows its volume.
# Left out:
# - exclude_windows_generic.xml: drops \srvsvc, \wkssvc, \lsass, \winreg, and \spoolss.
# - exclude_MSSQL.xml, exclude_postgres.xml, exclude_ibm_watson_explorer.xml, and
#   exclude_trend_micro.xml: exclude by pipe name alone, which an attacker can reuse.
# - exclude_adobe.xml, exclude_citrix.xml, exclude_fireeye_agent.xml, exclude_google_chrome.xml,
#   exclude_microsoft_edge.xml, exclude_microsoft_outlook.xml, exclude_mozilla_firefox.xml, and
#   exclude_qualys_agent.xml: "contains all C:\Program Files;..." also matches a folder such as
#   C:\Program Files2\, which a standard user can create. Chrome's and Edge's \mojo. pipe names are
#   also a common Cobalt Strike disguise.
# - exclude_call_manager.xml, exclude_citrix.xml, and exclude_microsoft_teams.xml: match programs
#   in user profiles. exclude_citrix.xml drops every pipe from them.
# - exclude_splunk.xml: an unanchored "end with" path.
# - exclude_azure_sentinel_agent.xml and exclude_qlik_sense.xml: products that weren't in the lab.
# exclude_powershell_pshost.xml drops the \PSHost pipe that powershell.exe creates in itself: 2,755 of
# the 3,192 pipe records in 6.6 hours of the October 7 test. A \PSHost pipe in any other process is
# still logged.
0_custom_configuration/elastic/modules/17_18_pipe_event/exclude_anonymous.xml
17_18_pipe_event/exclude_elastic.xml
17_18_pipe_event/exclude_openssh.xml
17_18_pipe_event/exclude_powershell_pshost.xml

# Event 25: process tampering. Logged in full: 7 records a day in the lab, 5 of them from Elastic Agent.
# Left out: every upstream exclusion. Event 25 reports the image of the process that was tampered
# with, and any user can start a legitimate program such as WMIADAP.exe or msedge.exe and replace its
# image, so excluding an image hides that program's hollowing. That applies to exclude_elastic.xml,
# exclude_firefox.xml, exclude_git.xml, exclude_microsoft_edge.xml, exclude_symantec.xml,
# exclude_unknown_process.xml, exclude_vscode.xml, and exclude_wmiadap.xml.
